# 因果识别假设与软件的边界（必须阅读）

CausalRank 输出的是**在模型与识别假设下的估计量**。把数值解释为因果效应之前，
使用者必须独立论证以下条件。**软件无法验证其中任何一条**；诊断只能暴露部分经验问题。

## 1. 识别假设

1. **一致性（consistency）**：个体实际接受 Treatment `a` 时，观测结果 $Y = Y(a)$。
   要求 Treatment 版本定义明确、结果定义与观察窗口在数据中一致。
2. **条件可交换性 / 无未观测混杂**：$Y(a) \perp T \mid X$ 对所有 $a$ 成立。
   即所有同时影响 Treatment 与结果的变量都已作为 `confounders` 输入。
   **遗漏强混杂会直接使 $\mu_a$ 有偏，且没有任何诊断可以发现它。**
3. **Positivity（共同支持）**：对所有 $x$ 与 $a$，$e_a(x) > 0$。弱重叠 → 极端权重 →
   高方差与模型外推。诊断（`low_propensity` / `low_ess` / `extreme_weight`）会警告，
   但**不能修复**；裁剪/截断会改变目标与偏差结构。
4. **SUTVA / 无干扰**：个体之间潜在结果互不影响，Treatment 无溢出效应。
5. **iid 抽样**：观测行独立同分布。若同一客户/家庭/机构有多行，或存在聚类与分层抽样，
   本版本的行级推断（含后续 Phase 2 的行 Bootstrap）不成立，需要 cluster bootstrap。
   软件只在检测到完全重复行时给出 `duplicate_rows` 提示。

## 2. 协变量的时序要求

`confounders` **必须测量于 Treatment 发生之前**。

- Treatment 后变量（中介、结果的组成部分、受 Treatment 影响的任何量）进入调整会
  阻断真实路径或引入碰撞偏差，估计不再对应 $E[Y(a)]$；
- 软件无法判断时序，只能靠使用者的数据字典保证；
- 自动判定“哪些变量是混杂/工具/中介/碰撞”明确不在本项目范围内。

## 3. 软件**不能**做什么

- 不能从数据证明“无未观测混杂”或一致性；
- 不能因 AUC / 准确率高就保证因果估计可靠（分类表现与因果有效性是两回事）；
- 不能因 `max|SMD| <= 0.1` 就宣布调整充分（那是筛查惯例，且只覆盖已测量变量）；
- 不能无条件从任意数据得出“因果排序”；
- 不能解决未观测混杂、违反 positivity、结果定义不一致的问题；
- 不提供个体层最优 Treatment 或收益最大化决策。

## 4. 报告用语的红线

- 区分 **模型估计**（$\hat e_a$, $\hat\mu_a$ 的数值）、**统计推断**（SE/CI/排名置信集，
  需显式启用联合 Bootstrap）与**因果识别条件**（上文假设）；
- 点估计排序 **不是** 统计上确立的排名；差异不显著 **不是** 效果相等的证据；
- 质量门控为 `caution` / `fail` 时，任何报告都必须原样呈现警告；
- 本软件**仅用于研究与方法验证**，不构成医疗、政策或商业决策建议。

## 5. 依赖与可复现性

- 数值结果依赖 numpy / pandas / scipy / scikit-learn 版本，版本记录在
  `result.metadata["versions"]`；发布前应锁定测试环境（`uv.lock`）；
- 相同数据 + 相同 `random_state` + 相同配置 → 相同结果（有测试覆盖）；
- 未设置 `random_state` 时结果不可复现，这是显式选择而非遗漏。
